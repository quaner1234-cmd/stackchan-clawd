# 小克的 Agent 状态表情

在家长控制窗口的“家长任务”页，用“用小克汇报 Agent 状态”独立开关控制。电脑和窗口须保持运行。只读取本地任务状态，不发送提示词、命令、聊天内容或凭据，不增加模型调用。

| 状态 | 小克的表现 |
| --- | --- |
| 正在运行 | 原有敲键盘动画，紫色呼吸灯，暂停被动轮播 |
| 等待批准或回答 | 原有疑惑表情，琥珀灯；空闲时抬头约6°、响两声轻提示音，然后恢复原角度 |
| 整个任务失败 | 原有难过表情、红灯，最长显示2分钟 |
| 全部任务空闲，刚有任务结束 | 跳原有8秒舞蹈；30秒内多个结束只跳一次 |

优先级为等待处理 → 失败 → 运行 → 最近结束。单条工具命令失败不代表整个任务失败。任务“结束”不等于代码已通过测试或部署成功。取消不跳舞；启动窗口不重播历史任务的完成动作。结束状态最多等待空闲2分钟，超时不再补跳，避免很久以前的任务突然庆祝。

孩子聊天、照片预览、原有舞蹈、闹钟、喝水/报时、手动方向和电脑音箱优先。状态提醒等空闲再执行；触屏仍走原来启动、取消、长按清空通道，不会批准电脑操作。用现有控制协议移动舵机，到位后释放电机；提示音为本地产生的24kHz PCM，遵循设备音量和静音设置。

## 接入与边界

- **Codex**：原生 `UserPromptSubmit`、`PermissionRequest`、`PostToolUse`、`Stop`、`Interrupt`、`SessionEnd` Hook；另只读本地 `state_5.sqlite` 指向的最近24个会话日志，读取任务开始/结束/中断事件，供正在运行的会话使用。Hook 由 Codex 自己审核信任，本工具不写信任记录、不自动批准。请自行审核新增 Hook，原 RTK 等配置保留；新 Hook 在实际会话生效仍要以事件文件为证，配置存在不等于已触发。
- **Hermes Desktop**：读取已有 `agent.log` 中 `tui prompt accepted` / `tui turn finished` 的明确任务边界；批准和提问用 profile 的 `xiaoke-status` 原生插件观察。没有修改 Hermes 核心源码。插件需后端重新启动加载，不会为此强制关闭正在工作的会话。
- **OpenCode**：全局自动加载 `xiaoke-status.js`，观察 `session.status` / `session.error` / `permission.asked` / `permission.replied`。多个批准并存时，要全部答复才解除等待；历史空闲事件不触发舞蹈。插件需后端下一次启动加载。

Codex 当前 Stop Hook 和日志结束事件没有可靠的整轮业务失败字段，因此普通结束只按“任务结束”处理，不能声称所有 Codex 错误都会显示难过。批准后的运行状态要等 PostToolUse 返回，长命令期间疑惑表情可能晚恢复。Hermes 与 Codex 的日志格式是当前安装版本的兼容读取；升级后需重新验证。失联状态最长6小时过期，不能把静默当作完成；刚打开窗口时可能识别不到很长日志中早已开始的任务，下一轮原生 Hook 可补齐。

事件邮箱 `agent-events/` 只保留 Agent 名称、会话ID的哈希、状态和时间，不含任务内容。窗口关闭后停止观察；关闭开关恢复旧有的家长任务显示。邮箱和开关设置均不公开提交。

## 检查与恢复

`test_agent_status.py` 检查优先级、过期、去重、隐私、子任务错误边界、聊天互斥、禁用、原生 Hook 无批准输出以及音频排空；`node test-agent-plugin.mjs` 检查 OpenCode 原生事件。`check-agent-status.py` 用受控状态连接真实硬件，检查实际显示、抬头/回位、PCM播放、原生短按同路启动/取消、完成舞蹈及本地唤醒恢复。它不调用云、不拍照，不保存房间音频。真人听感、实际手指触屏、多 Agent 的真实批准流程和长时间运行须单独验收，不能用注入状态冒充真实 Agent 触发。

刷写前请自行核验并保存设备固件、实际分区和恢复方法，只写核对后的应用分区。本仓库不公开本机备份或含硬件身份的回退脚本。外部适配器可用安装器的 `--rollback` 撤销；它拒绝覆盖安装后被其他人修改过的文件。

官方接入说明：[Codex Hooks](https://learn.chatgpt.com/docs/hooks)、[OpenCode Plugins](https://opencode.ai/docs/plugins/)。Hermes 按本机 `hermes_cli/plugins.py` 与 `tui_gateway/prompt_turn.py` 的实际实现对接。无额外驱动、服务购买或系统权限策略变更。
